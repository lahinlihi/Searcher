# 5부 — "왜"를 받고 배우기 (이유 칩과 자격 확인 표시) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 공고를 제외하거나 검토한 이유를 칩으로 받고, 쌓인 이유에서 규칙 후보를 뽑아 확인받은 뒤, 규칙에 걸리는 공고에 "자격 확인 필요" 표시를 붙인다.

**Architecture:** 이유와 규칙의 저장·판단은 새 모듈 `reasons.py` 하나에 둔다(순수 함수 + DB 함수). API 는 새 블루프린트 `routes/reasons.py`. 기존 목록 API 는 응답 dict 에 `eligibility_flags` 만 덧붙인다 — 적합도·순서·`dismissed_tenders` 표는 건드리지 않는다. 화면은 `tender-row.js` 의 순수 함수와 작은 칩 선택기로 붙인다.

**Tech Stack:** Flask, Flask-SQLAlchemy(sqlite), 바닐라 JS, pytest, node(순수 함수 확인)

**Spec:** `docs/product-contract.md` 의 "5부 — "왜"를 받고 배우기" (34~40절)

## Global Constraints

- 이유와 규칙은 **계정별**이다. 모든 조회·저장에 `user_id` 조건이 붙는다. 다른 계정의 자료가 표시에 영향을 주면 안 된다.
- 규칙에 걸린 공고의 **적합도와 목록 순서는 바꾸지 않는다.** `relevance.py`, `scoring.py` 는 수정하지 않는다.
- 규칙은 사용자가 [표시하기]를 누르기 전에는 어떤 공고에도 표시를 붙이지 않는다.
- 메모 본문과 공고 제목을 외부 AI 로 보내지 않는다.
- `dismissed_tenders` 표의 구조와 기존 60건(이유 없음)은 그대로 둔다. 이유는 별도 표에 붙인다.
- 제목 맞춤은 관심 키워드와 같은 규칙: `routes.tenders._TITLE_SEARCH_STRIP_CHARS`(공백·가운뎃점 등)를 양쪽에서 지우고 대소문자 무시 부분 일치.
- 규칙 후보 문턱: 근거 `MIN_EVIDENCE = 3` 건 이상, 반례 0건.
- 이유 코드와 표시 문구(정확히 이 값):

| 묶음 `group` | 코드 | 문구 |
|---|---|---|
| `ineligible` | `size` | 규모 제한 |
| `ineligible` | `region` | 지역 제한 |
| `ineligible` | `license` | 업종·등록 요건 |
| `ineligible` | `record` | 실적 요건 |
| `ineligible` | `target` | 대상이 다름 |
| `other` | `field` | 사업영역이 다름 |
| `other` | `budget` | 금액·기간이 안 맞음 |
| `other` | `cancelled` | 공고 취소·변경 |
| `other` | `etc` | 기타 |
| `like` | `like_field` | 분야가 맞음 |
| `like` | `like_form` | 해 본 수행 형태 |
| `like` | `like_agency` | 발주처 때문에 |

  `eligible` 은 계약서 36.3·36.4 가 말하는 "자격 가능으로 남긴 것"을 담는 칩이다(36.1 의 표에는 빠져 있어 이 계획에서 더한다 — Task 7 에서 계약서에 반영).
- 제외(`dismiss`)할 때 받을 수 있는 이유는 `ineligible` 과 `other` 묶음뿐이다.
- 테스트 실행: `python -X utf8 -m pytest tests -q -p no:cacheprovider`. "키워드 없는 계정"이 필요한 테스트는 `make_prefs(u)` 로 빈 설정 행을 만든다(없으면 `data/settings.json` 으로 떨어진다).

```python
import pytest
import reasons as RS

def test_options_cover_every_code_once():
    codes = [o['code'] for o in RS.options()]
    assert codes == list(RS.REASONS) and len(set(codes)) == 13
    assert {o['group'] for o in RS.options()} == {'ineligible', 'other', 'like', 'eligible'}

def test_clean():
    assert RS.clean(['size', 'region', 'size']) == ['size', 'region']
    assert RS.clean([]) == []
    for bad in (['nope'], 'size', None, [1], [['size']]):
        with pytest.raises(ValueError):
            RS.clean(bad)
    with pytest.raises(ValueError):
        RS.clean(['like_field'], groups=RS.DISMISS_GROUPS)
    assert RS.clean(['etc', 'license'], groups=RS.DISMISS_GROUPS) == ['etc', 'license']

def test_set_replaces_and_is_per_user(app, make_user, make_tender):
    a, b, t = make_user(), make_user(), make_tender()
    assert RS.set_reasons(a.id, t.id, ['size', 'region']) == ['size', 'region']
    RS.set_reasons(b.id, t.id, ['field'])
    assert RS.set_reasons(a.id, t.id, ['license']) == ['license']        # 통째로 바뀐다
    assert RS.get_reasons(a.id, [t.id]) == {t.id: ['license']}
    assert RS.get_reasons(b.id, [t.id]) == {t.id: ['field']}             # 남의 것은 그대로
    RS.set_reasons(a.id, t.id, [])
    assert RS.get_reasons(a.id, [t.id]) == {}

def test_set_rejects_unknown_code_without_changing_anything(app, make_user, make_tender):
    u, t = make_user(), make_tender()
    RS.set_reasons(u.id, t.id, ['size'])
    with pytest.raises(ValueError):
        RS.set_reasons(u.id, t.id, ['size', 'bogus'])
    assert RS.get_reasons(u.id, [t.id]) == {t.id: ['size']}
```
