# 신규사업 발굴 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 관심 키워드에 걸리지 않아도 "수행 형태는 해 본 것, 분야는 새로운" 진행 중 공고를 `/discover` 에서 걸친 발·새로운 발과 함께 보여 주고, 키워드를 제안 → 시험 4주 → 정식 또는 퇴장으로 돌린다.

**Architecture:** 고르는 로직은 새 모듈 `discover.py`(한 발 걸친 공고)와 `trial_keywords.py`(시험 키워드)에 두고, `routes/discover.py` 가 API 와 화면을 낸다. 수행 형태는 기존 `scoring._detect_business_type`, 닮음은 저장된 제목 벡터(`tender_vectors.load`)와 `case_scoring.knn_scores` 를 쓴다. 대시보드 본 목록과 적합도는 건드리지 않는다.

**Tech Stack:** Flask, Flask-SQLAlchemy(sqlite), numpy, pytest, 바닐라 JS(`static/js/tender-row.js` 재사용).

**Spec:** `docs/product-contract.md` 4부 (27~33절)

**선행:** `docs/superpowers/plans/2026-11-25-relevance-rescale.md` 가 끝나 있어야 한다 (공고 dict 를 `relevance.Scorer` 로 만든다).

## Global Constraints

- `scoring.py` 를 바꾸지 않는다. 발굴 전용 잡음 거르기는 `discover.NOISE_WORDS` 에 둔다.
- 유사도 기준: 한 걸음 `NEAR_SIM = 0.60` 이상, 두 걸음 `FAR_SIM = 0.50` 이상 0.60 미만. 0.50 미만은 어떤 경우에도 내놓지 않는다.
- "해 본 형태" = 좋은 사례(담은 공고 ∪ 사례)에서 2건 이상 확인된 사업 유형, '기타' 제외.
- 좋은 사례 5건 미만(`case_scoring.MIN_CASES`)이면 발굴을 하지 않고 안내만 한다.
- 한 번에 15건. 가까운 순.
- 시험 기간 `TRIAL_DAYS = 28`. 정식 키워드 정리 후보 기준 `STALE_DAYS = 180`.
- 요청 처리 중 임베딩 모델을 부르지 않는다(`tender_vectors.load` 만).
- 사람 승인 없이 관심 키워드(`UserPreference`)를 넣거나 빼지 않는다.
- 발굴 결과가 0건이면 빈 화면으로 넘기지 않고 이유(후보 수·형태 수)를 응답에 담는다.
- 테스트: `python -m pytest tests -q -p no:cacheprovider`. 커밋은 사용자가 요청할 때만.

## Review Focus

- 담은 공고가 전부 '기타' 유형이다 → 해 본 형태가 비어 있다. 오류가 아니라 "형태를 알 수 있는 공고를 더 담아 주세요" 안내가 나와야 한다. (Task 1)
- 시험 키워드가 정식 관심 키워드와 겹치거나 포함 관계다("AI" 와 "AI교육") → 후보로 내지 않고, 등록도 막는다. (Task 3)
- 같은 사업의 재공고·정정공고가 발굴 목록을 채운다 → 제목이 같은 공고는 하나만 낸다. (Task 1)
- 시험 기간이 끝났는데 사용자가 한 달 넘게 들어오지 않았다 → 다음에 열 때 정리된다(스케줄러 없이 조회 시점에 판정). (Task 4)
- 발굴에서 [아님]한 공고가 대시보드에서도 사라진다 → 안 된다. 발굴 전용으로만 숨긴다. (Task 2)
