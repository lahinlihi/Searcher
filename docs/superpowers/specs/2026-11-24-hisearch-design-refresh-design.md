# 하이-서치 디자인 개편 설계 (B 목록형)

작성 2026-11-24. 상태: 시안 확정(사용자, 2026-11-24 "이대로 확정"), 적용 계획 승인 대기.

## 의도

- 사이트가 "AI로 뚝딱 만든" 느낌이 난다. **판매용 사이트처럼** 보이게, 하이-잡과 같은 수준과 결로 맞춘다 (사용자).
- 전체 구조를 크게 바꾸는 것이 아니라 **공고 하나하나가 잘 보이게** 하는 것이 목적이다 (사용자).
- 한 번 적용하면 되돌리기 어려우니 시안을 보고 고른 뒤 정식 적용한다 (사용자). 시안은 확정됐다:
  https://claude.ai/artifact/RPBi7WfKsqCTrhznzP6so1 — **B. 목록형**, B. 공고 상세, B. 휴대폰 목록.

## 하지 않을 것

- 화면 뒤의 동작(API, 점수 계산, 검색 조건, 크롤)은 바꾸지 않는다. 바뀌는 것은 HTML·CSS·화면 JS 의 그리는 부분뿐이다.
- 메뉴 구성·주소(URL)를 바꾸지 않는다. 옛 주소는 그대로 동작한다.
- React·빌드 도구를 들이지 않는다 (지금의 Flask 템플릿 + Tailwind CDN + 바닐라 JS 를 유지).

**공고 한 건의 표시 규칙** (모든 목록 공통):
- 마감 블록: 오늘·D-1·D-2 빨강, D-3~7 주황, 그 이상 회색. 오늘이면 "오늘 마감", 마감일 없으면 "상시".
- 금액: 굵게. 1억 이상 "5.5억"(소수 한 자리), 미만 "3,000만원", 없으면 흐리게 "금액 미정".
- 구분 칩: 사전규격(남색) · 나라장터 입찰(주황) · 기타 채널(초록).
- 적합도 숫자 + 사례 점수(보라 칩, 마우스를 올리면 가장 비슷한 사례 제목). 사례 점수는 서버가 보낼 때만.
- 제목은 굵게 16px(휴대폰 15px), 기관은 보조 글자.

## 화면별 적용

1. **공통 틀(base.html)**: 흰 상단 막대 — 왼쪽 HIGH-SEARCH 글자 로고(기존 이미지 로고는 같은 자리에 유지할지 적용 때 사용자 확인), 가운데 둥근 검색창, 오른쪽 주 메뉴. 메뉴가 많으므로 주 메뉴는 대시보드·상세검색·관심공고·놓친 공고·검토공고, 나머지(필터관리, 뉴스레터, 회원관리, 설정, 로그)는 "관리" 펼침 메뉴로 묶는다 (작성자 판단). 휴대폰은 메뉴 버튼으로 펼친다.
2. **대시보드**: B 목록형. 왼쪽에 요약 4칸·관심 키워드·필터(마감·구분·금액), 오른쪽에 구분 탭(전체/사전규격/나라장터 입찰/기타 채널/비슷한 공고)과 정렬(마감 임박순·적합도순·사례순), 한 줄 목록. "오늘 볼 것" 요약 칸은 화면에 있는 목록에서 계산한 사실만 쓴다(오늘 마감 건수, 사례 70 이상 건수, 가장 큰 사업). 지금 API(`/api/dashboard`, `/api/cases/similar`, `/api/embed-scores`)를 그대로 쓴다.
3. **공고 상세**: B 상세. 핵심 4칸(배정예산·입찰 마감·개찰·참가 제한), 공고 정보 표, 공고문 AI 분석, 팀 메모, 오른쪽 판단 칸(마감 블록·원문 보기·담기/관심없음·적합도 막대·사례·과거 이력). 지금 상세 화면의 기능(투찰 금액 계산, 연관 공고 등)은 모두 남긴다.
4. **상세검색**: 결과 목록을 대시보드와 같은 한 줄 목록으로. 왼쪽 검색 조건은 B의 필터 모양으로.
5. **나머지 화면**(관심공고, 검토공고, 놓친 공고, 로그, 설정, 회원관리, 로그인 등): 공통 버튼·칩·카드·표 규칙으로 맞춘다. 배치는 크게 바꾸지 않는다.
6. **뉴스레터 통합 편집실·구독사 화면**(계약서 2부): 처음부터 이 규칙으로 만든다.

## 방식

- 공통 규칙은 새 파일 `static/css/hs-theme.css`(토큰 + 공용 클래스 `hs-btn`, `hs-chip`, `hs-card`, `hs-dd`, `hs-row` 등)에 둔다. 기존 `style.css` 는 화면별 적용이 끝날 때까지 남기고, 다 옮긴 뒤 안 쓰는 규칙을 지운다.
- 공고 한 줄을 그리는 JS 는 `static/js/tender-row.js` 한 곳에 두고 대시보드·검색·관심공고가 함께 쓴다(지금은 화면마다 카드 그리는 함수가 따로 있다).
- 작업은 별도 브랜치(worktree)에서. 화면마다 운영 DB 사본을 띄운 임시 서버에서 PC·휴대폰 폭으로 확인하고, 사용자에게 보여 준 뒤 다음 화면으로 간다.

## 검증 기준

- 각 화면이 오류 없이 열린다(콘솔 오류 0, 서버 오류 0). 로그인한 상태로 모든 페이지를 여는 자동 테스트를 둔다.
- 대시보드·검색의 **공고 목록과 순서는 개편 전과 같다**(API 응답 비교). 바뀌는 것은 모습뿐이다.
- 휴대폰 폭 390px 에서 가로 스크롤이 없다.
- 글자 대비 4.5:1 이상(보조 글자 #666C77 on #FFFFFF = 5.7:1).
